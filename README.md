# Bitrix24 Scoring Handler

Внешний обработчик скоринга для сделок Bitrix24 в воронке `Продажи` (`CATEGORY_ID=0`).

## Что делает

- принимает событие сделки на `/bitrix/scoring`;
- читает сделку через Bitrix24 REST;
- рассчитывает `Рекомендация по скорингу`;
- подставляет план трудозатрат после выбора `Формат просчета`;
- записывает только:
  - `UF_CRM_SC_RECOMM` — рекомендация;
  - `UF_CRM_SC_REASON` — причина рекомендации и рекомендуемое действие;
  - `UF_CRM_SC_INPUT_HASH` — служебный слепок входных полей скоринга;
  - `UF_CRM_EST_PLAN_HOURS` — план трудозатрат на просчет;
  - `UF_CRM_EST_INPUT_HASH` — служебный слепок выбранного формата просчета.

Пересчет выполняется только когда изменились входные поля скоринга: направление, тип компании, бюджет, ЛПР/ЛВР, интерес или конкретика запроса. Если менеджер меняет комментарий, задачу, название сделки или другое поле, обработчик пропускает обновление.

План трудозатрат пересчитывается только когда изменился `Формат просчета`. Если менеджер вручную скорректировал план без смены формата, обработчик не перетирает ручное значение.

Обработчик не двигает сделку по стадиям, не закрывает ее автоматически и не блокирует переходы между стадиями.

## Запуск

```bash
npm install
npm start
```

Настройки лежат в `.env`:

```bash
PORT=8787
BITRIX24_WEBHOOK_URL=...
SCORING_SECRET=...
BITRIX24_DEAL_CATEGORY_ID=0
```

## Проверка

```bash
npm test
curl http://localhost:8787/health
```

Dry-run без записи в CRM:

```bash
curl "http://localhost:8787/bitrix/scoring?secret=$SCORING_SECRET&dryRun=1&dealId=8507"
```

## Правило

`Отказ`, если малый бизнес, нецелевое направление, нет интереса, нет пути к ЛПР или для среднего бизнеса/стартапа бюджет ниже 3 млн рублей.

`Берем в работу`, если направление `Web` или `ИИ`, интерес подтвержден, ЛПР/путь к ЛПР есть, запрос конкретный, а бюджет проходит регламент. Для `Энтерпрайз` и `Гос` бюджет может быть неизвестен на первом шаге.

Во всех остальных потенциальных случаях ставится `Доразведка`.

## Формат просчета

После выбора `Формат просчета` обработчик подставляет плановые часы:

- `Не считаем` — `0`;
- `Экспресс-оценка / вилка` — `2`;
- `Верхнеуровневый просчет КП` — `6`;
- `Детальный просчет / декомпозиция` — `20`;
- `Демо решения / прототип` — `40`.

Техлид подключается только на формате `Детальный просчет / декомпозиция`.

Центральные поля блока:

- `Формат просчета`;
- `План трудозатрат на просчет, ч`;
- `Причина выбора формата / допущения`.

## Bitrix24

Создан рабочий исходящий webhook для пилота, который вызывает публичный HTTPS endpoint обработчика при событиях:

- `ONCRMDEALADD`;
- `ONCRMDEALUPDATE`.

Для временного туннеля при смене публичного адреса нужно создать новый исходящий webhook или обновить URL текущего.

Временные туннели подходят только для проверки. Для рабочей эксплуатации обработчик нужно разместить на постоянном HTTPS-хостинге и заменить URL в исходящем webhook.

## Контроль перехода

Обязательные поля настраиваются штатным функционалом Bitrix24 по принципу **с этапа**.

С `Целевой Лид` (`UC_6M9M15`):

- `Тип проекта / направление`;
- `Тип компании`;
- `Бюджет проекта`;
- `ЛПР/ЛВР`;
- `Интерес подтвержден`;
- `Запрос конкретный`;
- `Решение по квалификации`.

С `Пресейл / КП готовится`:

- `Формат просчета`;
- `План трудозатрат на просчет, ч`;
- `Причина выбора формата / допущения`.

С `КП отправлено`:

- `Сумма и валюта`;
- `Ссылка на смету`.

Внешний обработчик отвечает за расчет `Рекомендация по скорингу`, `Причина рекомендации` и автоподстановку плановых трудозатрат. Он не управляет стадийной обязательностью полей.
